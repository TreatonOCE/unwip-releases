Safety for the things most likely to go wrong:
- Books now record which version of Unwip stored them. An older Unwip won't open a book saved by a newer one (it asks you to update instead), and if another computer saves a book in a newer way while it's open here, this one stops saving the binder rather than damage it. Your chapters keep saving.
- If a future update ever changes how books are stored, each book is backed up before it's changed. Installing an update also backs up the book that's open first.
- If saving fails (a full disk, a folder Unwip isn't allowed to write to, a file locked by another program), a warning stays at the top until it works again, saying why. Your words stay on screen and are saved by themselves once the problem is fixed, even if you've moved to another chapter. Leaving the book or closing the window asks first.
- Very long folder paths on Windows (a deep binder exported into a deep Dropbox folder) are handled, and book names Windows can't use as folder names (like "CON" or a name ending in a full stop) are made safe.
- Scrivener import: if the project's main file is damaged, Unwip uses Scrivener's own spare copy of the binder and tells you. Missing or damaged chapter files are named in the import report instead of quietly coming in empty. If an import stops partway (a full disk, say), the half-made book is removed.
- New: What I've used (About › What I've used, or search "used"). A private tally of which buttons, menus, settings and shortcuts you use, and which are on screen but never used, to help decide what to tuck away later. It stays on this device, keeps no writing or names, and changes nothing.
